# Настройки, данные и файлы

## Конфигурация приложения

`AppConfig` объявлен в `core/config.py`. Основные поля:

| Поле | Назначение |
| --- | --- |
| `bot_token` | Токен Telegram-бота. |
| `download_root` | Корень локального хранения медиа. По умолчанию `D:\TikTok`. |
| `autostart` | Состояние автозапуска Windows. |
| `defaults` | Значения доставки, размера пачки, лимита хранения и качества по умолчанию. |
| `command_aliases` | Алиасы команд Telegram. |
| `admin_ids` | Список admin ID из конфигурации. |
| `users` | Индивидуальные настройки, индексируемые строковым user ID. |

Настройки записываются в `config.json` в выбранной data directory. `storage.json` рядом с приложением хранит указатель `data_dir`, когда выбран путь для каталога данных.

## Выбор папок

Порядок определения каталога конфигурации в `core/config.py`:

1. Путь из `storage.json`, если он существует и корректно читается.
2. Папка приложения, если рядом уже есть `config.json`.
3. `%LOCALAPPDATA%\TikTokDownloader`, если переменная окружения задана.
4. Папка приложения как fallback.

Путь загрузок задается `download_root`, затем переменной окружения `DOWNLOAD_ROOT`, иначе используется `D:\TikTok`. Для каждого пользователя создается подпапка по числовому Telegram user ID. `get_user_dir()` проверяет, что разрешенный путь остается внутри корня загрузок.

## Важная связь при сохранении из GUI

Текущее поведение `SettingsService.save()` использует выбранный `download_root` как аргумент для `set_app_data_dir()` и одновременно сохраняет его как `cfg.download_root`. Поэтому после сохранения UI папка загрузок становится также data directory для `config.json`. Учитывайте это при изменении поведения папок или описании установочного сценария.

Значение токена в конфигурации хранится локально в JSON. Не коммитьте реальные `config.json` или `cookies.txt` и не включайте их содержимое в диагностику/документацию.

## Состояние во время работы

- Очередь `Job` и счетчики находятся в оперативной памяти `JobQueueService`.
- Видео после скачивания хранятся в файловой системе в пользовательской подпапке.
- Пользовательские настройки сериализуются в JSON-конфигурацию.
- В runtime есть отдельные lock-объекты для последовательной обработки пользователя и защиты flush.
- `queue_keep_max` задается настройкой/командой `/keep`; само наличие настройки не означает, что автоматическое удаление старых файлов реализовано.

## Локальные файлы и секреты

В корне репозитория есть `config.json` и `cookies.txt`. Это потенциально чувствительные локальные данные; их содержимое не анализировалось и не должно попадать в карту проекта. При публикации репозитория проверьте `.gitignore` и историю Git отдельно.
